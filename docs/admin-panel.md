# Bot 管理控制台

控制台和 Bot 运行在同一台服务器上，默认仅监听服务器的
`127.0.0.1:8090`。请不要在防火墙中开放该端口，也不要将
`BOT_ADMIN_HOST` 改为 `0.0.0.0`。

## 服务器配置

在服务器仓库根目录的 `.env` 中设置一个随机、独立的管理令牌：

```env
BOT_ADMIN_TOKEN=replace-with-a-long-random-secret
BOT_ADMIN_HOST=127.0.0.1
BOT_ADMIN_PORT=8090
```

重启 Bot 后，日志会显示控制台已经在 `http://127.0.0.1:8090` 启动。
未配置令牌时，控制台不会启动。

## 从个人电脑访问

在个人电脑终端建立 SSH 隧道，并保持该命令运行：

```bash
ssh -N -L 8090:127.0.0.1:8090 ubuntu@your-server
```

如果服务器的 SSH 端口不同，追加 `-p <port>`；如使用私钥，追加
`-i <private-key-path>`。

然后在个人电脑的浏览器打开：

```text
http://127.0.0.1:8090
```

输入服务器 `.env` 中的 `BOT_ADMIN_TOKEN` 登录。浏览器请求会经由 SSH
加密隧道发送到服务器本机，不会公开 Bot 控制台端口。

## 菜单与指令面板

登录后搜索“菜单”或“面板”，可使用查询/修改全局菜单、面板列表、创建、
详情、修改、删除和关联对象管理，共 8 项操作。仍使用现有管理令牌与 SSH
隧道，不需要新增配置或在浏览器填写 QQ API 凭据。

建议先查询并保存原始 JSON，再执行修改。菜单和面板修改是完整覆盖；
表单中的配置 JSON 直接填写 `{"items": [...]}`，不要套外层 menu/panel。
输入框的灰色示例只是提示，不会自动作为提交值。
场景、作用范围与关联操作使用带中文说明的下拉菜单，初始为“请选择”，
不会自动替用户选择生效范围。服务端也会校验选项，不能通过手工请求绕过。

创建全局面板：scope 填 c2c/group/channel/dm，target_type 填 all，
关联对象字段留空。创建指定对象面板：scope 填 c2c 或 group，target_type
填 specific，并在对应的 user_openids 或 group_openids 中填写 JSON 数组，
例如 `["openid1", "openid2"]`，一次最多 20 个。不要同时填写两类对象。
修改关联对象的 op 为 add 或 del，channel/dm 和 all 面板不支持此操作。

列表查询返回 next_cursor/is_end；未结束时将 next_cursor 填入游标框继续查询。
写操作提交前会弹出确认；删除仅对指令面板开放，不开放其他资源删除或消息撤回。
浏览器确认用于防误操作，不代替服务端鉴权。删除没有一键撤销，若需恢复，
须用之前保存的配置重新创建面板并重新关联对象。

QQ API 未返回结果时控制台会提示超时。写操作超时可能已经生效，应先查询确认，
不要直接重试创建或覆盖操作。限频见各操作说明，控制台不会自动轮询或重试。
新增接口已进行离线测试，但实际权限与线上效果仍需用机器人账号验证。
