# 频道区间总结

在同一文字子频道内依次：引用起点消息发送 `/总结起点`，引用终点消息发送
`/总结终点`，最后单独发送 `/开始总结`。区间包含两端消息。重新设置起点会
清除旧终点；标记按 guild、子频道、发起用户隔离，仅在内存保存消息 ID，
30 分钟过期，服务重启后失效，最多保留 2048 组标记。

复用 `config/chat.yaml` 的 enabled 和 allowed_channel_ids；只有已开放
AI 聊天的子频道能使用。使用已有模型环境变量，单独创建不联网的模型客户端，
不携带聊天历史、不运行工具、不保存原始记录或总结，不写入个人会话。
待总结内容会发送到配置的模型供应商，命令帮助中明确说明。
模型请求与聊天共用每用户每日额度；读取失败和输入超限不消耗模型额度。

`botpy_ext/channel_history.py` 补充 Python SDK 未封装的
`GET /channels/{channel_id}/messages?before=...&limit=20`，从终点向前分页，
优先按接口返回的 `seq_in_channel` 排序，缺失时使用带时区的 `timestamp`，
不推断消息 ID。缺少序号且起止时间相同、起点同时间存在其他消息或翻页边界
时间无法区分时拒绝生成，避免跳过消息。官方 Go SDK 的
[消息列表实现](https://github.com/tencent-connect/botgo/blob/master/openapi/v1/message.go)
和[消息结构](https://github.com/tencent-connect/botgo/blob/master/dto/message.go)
作为接口依据。实际机器人是否有历史读取权限仍须单独联调确认。

起止消息分别查询并校验子频道；缺失起点、分页不推进、反向范围、超限等情况
拒绝调用模型，不悄悄总结部分区间。最多 500 条可见消息，同时受现有
max_context_chars 限制。只处理文本，附件仅标记数量，不下载或 OCR。
删除及机器人不可见的消息无法恢复，总结注明仅基于接口实际可见消息。

消息正文和昵称按不可信 JSON 数据传入独立总结提示词，禁止执行历史消息中的
指令，不带入聊天人设。并发数使用现有 max_concurrent_requests；总时限为
模型请求时限加 90 秒，最高 180 秒。关闭服务时取消未完成任务并关闭连接。
本阶段只有离线验证，不发送真实 QQ 消息或调用付费模型。
