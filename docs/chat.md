# 频道 AI 聊天（第一版）

默认关闭，无需配置密钥即可正常启动 Bot。使用显式 `/聊天`（别名 `/chat`），
不接管未知命令、不自动采集普通频道发言，不提供联网、工具或流式输出。

## 开启

1. 在根目录 `.env` 填写 `CHAT_API_KEY`；留空时使用原有 `ZHIPU_API_KEY`。
   不要把真实密钥发给聊天助手、提交 Git 或填写到 YAML。
2. `CHAT_BASE_URL` 默认为 `https://open.bigmodel.cn/api/paas/v4`，
   `CHAT_MODEL` 默认为旧配置的 `glm-4.5-flash`。地址不包含 `/chat/completions`。
   这里只实现兼容的非流式 Chat Completions 协议，不保证所有供应商、模型的参数兼容。
   模型是否仍对账号开放，需要真实测试；不配置自动供应商回退或重试。
3. 编辑 `config/chat.yaml`：设置 `enabled: true`，将测试子频道 ID 作为带引号的
   字符串加入 `allowed_channel_ids`，例如 `["723086974"]`。空白名单不开放任何频道。
4. 备份 `user.db`，重启 Bot。仅新增聊天表，旧 `sessions.json` 保留，不自动导入。
5. 测试 `/聊天 你好`、`/聊天 /reset`、`/聊天 /stop`、`/帮助 聊天`。

## 行为与限制

- 会话按频道组、子频道、用户隔离；同一会话只允许一条在途请求，不同用户可并发。
- 默认最多 3 个模型请求同时执行，在途/排队总数最多 20；等待和生成合计超时 45 秒。
- `/reset` 增加版本并取消旧请求；`/stop` 取消生成而保留已成功对话。
  取消上游请求不保证供应商不计费。已提交 QQ 的消息不能因取消自动撤回。
- 成功收到 QQ 消息 ID 后，才把完整提问/回答加入有效上下文。拒收、未知响应不加入。
  304023 审核中保存为 pending，暂不自动跟踪审核结果，也不进入后续上下文。
- 每人北京时间每天最多 30 次已开始的模型尝试，跨频道共用额度，重置不清额度。
  网络失败、模型失败或生成后发送失败也占一次；此限制不是精确金额预算。
- 使用最多 50 个最近成功轮次，按完整轮次裁剪到上下文字符预算（默认 8000 字符，含提示词和输入）。
  **不是供应商精确 token 预算**，需按实际模型上下文容量保守配置；输出参数默认 800 tokens。
- 单次输入最多 2000 字符；译后回答超过 3500 字符时不发送、不加入上下文，提示缩短回答。
- 历史默认有效期 7 天，过期数据在后续聊天读历史时清理，不是到点立即删除。
  历史包含提问与回答，需限制数据库/备份访问；无活动时可停机清理过期数据。
- 通用 command_records 不保存聊天请求正文；不记录聊天原文到新增日志，频道 AT 入口不再打印原消息。
  不删除旧日志、旧命令记录、备份或供应商记录。聊天暂不计入原有通用命令用量榜单。
- 模型输入只来自显式请求与本人的当前会话。配置缺失/无效不会阻止其他 Bot 功能启动。
- 客户端随 Bot 关闭释放，失败不自动重发；SDK 本身可能记录成功发送的回答，应保持生产日志非 DEBUG。

## 验收与回滚

先只开放一个测试频道，确认模型权限、耗时、费用及 QQ 审核行为。测试本身不需要真实 key，
`tests/test_chat.py` 使用模拟模型/HTTP 响应。当前没有做真实模型调用或线上部署。

禁用：将 `enabled` 改为 false 并重启。代码回滚不会自动删除新增表或会话数据；
保留数据库备份，不要为了回滚删除整个 user.db。

当前未引入 dsh。之后如需其他模型或 Agent 工具，替换/扩展模型调用模块即可，
不应将任意 shell 或现有 Bot 写操作直接暴露给模型。
