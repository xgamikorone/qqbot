# 群聊命令接入

频道继续由 `on_at_message_create` 处理，群聊由
`on_group_at_message_create` 处理，C2C 单聊由 `on_c2c_message_create` 处理。
三者共用命令注册表和解析流程，但分别调用 `execute_guild`、`execute_group`、
`execute_user`，直接传递原始 `Message`、`GroupMessage`、`C2CMessage`。
频道的 `guild_id`、`channel_id`、成员及附件等 SDK 属性完整保留。
群消息正文已由平台移除机器人提及，不按频道格式跳过正文第一个词。

## 当前支持

- `/帮助`、`/所有命令`：仅展示已开放群聊的命令。
- `/time`：北京时间。
- `/答案之书 问题`、`/答案之书帮助`。
- `/最近更新`。
- 原有 `/hello` 探测保持可用。

C2C 当前仅开放答案之书、答案之书帮助和 `/帮助`，作为三场景执行示例。
频道私信 `DirectMessage` 与 C2C 是两种不同事件，原频道私信逻辑不变。

支持别名和 `&&` 命令链。每次群触发共享递增 `msg_seq`，包括失败的发送尝试；
多条回复仍受平台额度和有效期限制，本地不保证超出平台限制的回复成功。
未知、未迁移和作者命令会明确回复，群身份不复用频道作者权限。
`messaging/command_replies.py` 使用 `ContextVar` 管理每次事件的发送序号，
命令链共享，独立并发事件隔离。状态只保存发送所需信息，不替代 SDK 消息。

## 数据边界

在原数据库中增量创建 `group_members` 和 `group_command_records`，不改写
频道历史。成员主键为 `(group_openid, member_openid)`；只记录观察到的成员，
不是完整成员列表。缺失昵称为空，不通过内邀成员查询接口补全，也不虚构角色。
当前 SDK 会丢弃部分事件字段，包括昵称和角色。后续要增加角色管理时，
需先扩展 SDK 解析并补充权限测试。

命令记录不存正文和参数，保留群、成员、消息、命令名、链位置、成功状态和时间。
唯一约束避免同一事件重复计入统计，但不保证重复事件下业务副作用只发生一次。
C2C 使用独立的 `c2c_command_records`，仅记录用户 OpenID、消息 ID、命令名、
链位置、状态和时间，不保存私聊正文或参数，不与频道/群身份自动关联。

## 后续迁移

命令通过 `supported_scenes` 显式声明支持的 `guild/group/user` 场景，且必须
实现对应的执行方法。仅声明而未实现时仍拒绝执行；帮助目录采用同一判断。
通过基类的 `reply_guild/group/user` 发送，不在业务方法中判断消息类型。
答案之书的 `build_answer` 共用生成逻辑，三个执行方法只处理各场景呈现及回复。
普通群主和管理员不等于机器人作者，未建立独立权限模型前不开放作者命令。

旧命令的 `execute` 仍由基类 `execute_guild` 委托调用，旧 `after_execute`
由 `after_execute_guild` 委托调用，保留聊天命令不记录正文的既有策略。
群聊和单聊分别使用 `after_execute_group/user`，不调用频道入库流程。
`False` 表示失败并停止后续命令链；兼容期旧命令返回 `None` 视为正常完成。
原 `CommandContext` 和独立群分发器已移除。

图片上传、每日老婆、开创、排行榜及聊天尚未迁移。每日玩法需先确定按群隔离
的唯一约束及仓储接口；不能把群 ID 填进旧表的 `guild_id` 或把成员 OpenID
当成频道用户 ID。主播 UID/昵称和图片资源可继续共享。

群资料与成员列表接口有权限/内邀限制，基础命令不依赖它们。身份跨群、跨应用
及跨频道的关联留待明确契约或账号绑定流程确定。

本阶段只提供离线验证，不启动生产机器人或发送真实 QQ 消息。
