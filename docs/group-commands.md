# 群聊命令接入

频道继续由 `on_at_message_create` 处理，群聊由
`on_group_at_message_create` 处理，C2C 单聊由 `on_c2c_message_create` 处理。
三者共用命令注册表和解析流程，但分别调用 `execute_guild`、`execute_group`、
`execute_user`，直接传递原始 `Message`、`GroupMessage`、`C2CMessage`。
频道的 `guild_id`、`channel_id`、成员及附件等 SDK 属性完整保留。
群消息正文已由平台移除机器人提及，不按频道格式跳过正文第一个词。

## 当前支持

- `/帮助`、`/所有命令`：仅展示已开放群聊的命令。
- `/time`：北京时间。
- `/答案之书 问题`、`/答案之书帮助`。
- `/最近更新`。
- `/查bv <BV号>`：查询视频资料和封面，保留 `/查BV`、`/查视频` 别名。
  群封面先上传再随文字以富媒体回复；上传失败时回复文字资料和封面失败提示。
- `/复读 <文字> [图片附件]`：复读文字及第一张图片附件，保留 `repeat`、`echo`。
  非图片附件不作为图片发送；群昵称缺失时显示“一位朋友”。
- `/斗虫`、`/斗虫v2`、`/斗虫帮助`：保留原有参数、数据源和缓存规则，
  排行榜在本地绘制后通过群聊分片接口上传。两项冷却分别为 60 秒、10 秒，
  按命令全局共享，包括不同别名、频道和群聊；仅完整成功后开始计时。
- `/生日快乐 <过生日的人> [送祝福的人]`：群聊默认使用可用昵称，缺失时显示
  “一位朋友”；也可以手动指定。频道继续默认提及发起人。
- `/所有主播`：列出已收录主播及 UID，保留 `/收录主播`、`/all_streamers` 别名。
  群聊长列表按下述规则分段；空列表和查询失败分别提示。
- `/营收 <uid或昵称>`：当前注册的营收 V2，模糊昵称最多匹配 5 位主播。
- `/高能 [数量|all]`：保留固定分类、排除名单和默认前十展示规则。
- `/粉丝 [分类或主播名]`、`/舰长 [分类或主播名]`：当前数量，保留查询等待提示。
- `/查SC <uid或昵称> [页码]`：SC V2 接管旧命令，保留 `/查SCv2` 等别名。
- `/查舰长 <uid或昵称> [页码]`：查询上舰记录，支持模糊昵称，区别于当前舰长数。
  两项均从第 0 页开始，每页 10 条，最多匹配 5 位主播。
- 原有 `/hello` 探测保持可用。

C2C 当前仅开放答案之书、答案之书帮助和 `/帮助`，作为三场景执行示例。
频道私信 `DirectMessage` 与 C2C 是两种不同事件，原频道私信逻辑不变。

支持别名和 `&&` 命令链。每次群触发共享递增 `msg_seq`，包括失败的发送尝试；
多条回复仍受平台额度和有效期限制，本地不保证超出平台限制的回复成功。
未知、未迁移和作者命令会明确回复，群身份不复用频道作者权限。
`messaging/command_replies.py` 使用 `ContextVar` 管理每次事件的发送序号，
命令链共享，独立并发事件隔离。状态只保存发送所需信息，不替代 SDK 消息。

这批直播查询共用 `commands/text_query.py` 的频道/群聊入口，各命令实现
`query_and_reply(args, reply)`，不接收伪造消息对象。频道保留原文本回复，
群聊文本按应用设定的 1500 字符分段，尽量沿换行切分，不静默截断。
等待提示、结果分段和后续命令共享回复序号；平台回复额度、消息审核和
有效期仍可能限制发送，大结果建议使用数量参数、具体 UID 或 SC 页码缩小范围。

迁移时修复了 SC V2 多主播查询仅保留最后一位结果的问题，并对无效 UID、
SC 页码、营收空响应和查询超时提供提示。主播昵称表继续共享，不需要新建
业务表，调用记录使用已有群聊表。当前舰长数与上舰记录分别查询，
不开放管理员用户历史查询。

旧版 `RevenueCommand`、`SuperChatCommand` 已移除。`/查SC`、`SC`、`sc`、
`super_chat` 与 `super_chat_v2`、`查SCv2` 共用 `SuperChatCommandV2`，
保留其内部命令名 `super_chat_v2`，不改写历史调用记录。
`StreamerGuardsCommand` 使用同样的 UID/昵称解析和分场景回复机制。
管理员命令 `UserSuperChatCommand` 保持原有频道权限与行为。

## 数据边界

在原数据库中增量创建 `group_members` 和 `group_command_records`，不改写
频道历史。成员主键为 `(group_openid, member_openid)`；只记录观察到的成员，
不是完整成员列表。缺失昵称为空，不通过内邀成员查询接口补全，也不虚构角色。
SDK 原本会丢弃昵称和角色字段。项目的 `GroupNicknameClient` 在登录后、
接收事件前安装连接专属的群事件解析器，保留 `author.username`；消息仍是
原始 SDK `GroupMessage`，不修改第三方库文件或全局解析器。
角色字段仍未接入，昵称查询不授予权限；增加角色管理需另行补充权限测试。

复读和生日祝福需要显示名字时，共用 `messaging/group_names.py`：
优先事件昵称，其次群/成员隔离的内存缓存；缺失或过期时读取已有
`group_members.display_name` 并尝试成员接口更新。接口为
`GET /v2/groups/{group_openid}/members/{member_openid}`，只读取 `username`，
不调用成员列表接口。查询成功后昵称随正常命令记录保存，无需改表。
显式填写生日祝福人时不查接口。

成功昵称缓存 10 分钟，失败缓存 60 秒，内存最多 2048 项；并发查询合并，
全局请求间隔至少 2.1 秒，单次超时 2 秒。无权限（11253/403）暂停查询一小时，
之后可自动重试；失败保留已有昵称，全部缺失时仍显示“一位朋友”。
当前机器人的成员接口权限和实际事件昵称下发情况仍需平台联调确认。

命令记录不存正文和参数，保留群、成员、消息、命令名、链位置、成功状态和时间。
唯一约束避免同一事件重复计入统计，但不保证重复事件下业务副作用只发生一次。
C2C 使用独立的 `c2c_command_records`，仅记录用户 OpenID、消息 ID、命令名、
链位置、状态和时间，不保存私聊正文或参数，不与频道/群身份自动关联。

## 后续迁移

命令通过 `supported_scenes` 显式声明支持的 `guild/group/user` 场景，且必须
实现对应的执行方法。仅声明而未实现时仍拒绝执行；帮助目录采用同一判断。
通过基类的 `reply_guild/group/user` 发送，不在业务方法中判断消息类型。
答案之书的 `build_answer` 共用生成逻辑，三个执行方法只处理各场景呈现及回复。
普通群主和管理员不等于机器人作者，未建立独立权限模型前不开放作者命令。

旧命令的 `execute` 仍由基类 `execute_guild` 委托调用，旧 `after_execute`
由 `after_execute_guild` 委托调用，保留聊天命令不记录正文的既有策略。
群聊和单聊分别使用 `after_execute_group/user`，不调用频道入库流程。
`False` 表示失败并停止后续命令链；兼容期旧命令返回 `None` 视为正常完成。
原 `CommandContext` 和独立群分发器已移除。

通用群图片回复由 `Command.reply_group_image` 封装：调用 `post_group_file`
并设置 `srv_send_msg=False`，校验返回的 `file_info`，再以 `msg_type=7`
调用 `post_group_message`，附上原消息 ID 和共享序号。上传不消耗回复序号，
发送尝试消耗序号。仅上传失败允许文字降级，发送失败不重发视频结果。
这与独立的“图片上传”业务命令不同；后者仍未迁移。

本地图片通过 `Command.reply_group_local_image` 和
`botpy_ext/group_upload.py` 上传，不需要图床。协议依据本次提供的官方
富媒体概述、群聊预上传、分片确认截图：`upload_prepare` 提交文件名、
字符串格式大小、MD5、SHA1、前 10002432 字节的 MD5；按返回的分片大小
逐片 PUT 至预签名 HTTPS URL，随后调用 `upload_part_finish`；最后携带
`upload_id`、`file_type=1`、`file_name`、`srv_send_msg=False` 调用 `/files`
合并并获取 `file_info`。此流程的真实平台响应仍需上线联调确认。

兼容 SDK 将带 charset 的 JSON 响应作为字符串返回的情况。上传失败日志只记录
`stage=read/prepare/plan/put/confirm/merge/media` 和固定校验原因或异常类型；
富媒体发送失败记录 `stage=send`。不输出预签名 URL、原始响应或网络异常正文。

末片的 `block_size` 兼容实际长度和统一分片容量两种返回方式。实际 PUT、
分片确认长度和 MD5 始终根据文件剩余字节计算，不为末片填充数据；
兼容从 0 或 1 开始的连续序号（实际群聊接口已观察到从 1 开始），
按排序后的位置计算文件偏移，确认时使用服务端原始序号。继续拒绝重复、
跳号、负序号及其他起始值，并校验分片数量及异常大小。

只接收非空、至多 20 MB 的本地图片，避免超过图片限制后降级成文件。
读取有大小上限的文件快照，校验分片序号、数量和总长度；串行上传，
分片 PUT 最多尝试三次，整体上传限时 240 秒。PUT 使用独立 HTTP 会话，
不继承 QQ 认证头、Cookie 或环境代理，不跟随重定向，也不记录签名 URL。
上传完成前不分配回复序号；图片发送失败不自动重发，命令链停止。
两个排行榜共用绘图锁，在工作线程中串行绘图；发送结束或失败后清理临时文件。

每日老婆、开创、排行榜及聊天尚未迁移。每日玩法需先确定按群隔离
的唯一约束及仓储接口；不能把群 ID 填进旧表的 `guild_id` 或把成员 OpenID
当成频道用户 ID。主播 UID/昵称和图片资源可继续共享。

群资料与成员列表接口有权限/内邀限制，基础命令不依赖它们。身份跨群、跨应用
及跨频道的关联留待明确契约或账号绑定流程确定。

本阶段只提供离线验证，不启动生产机器人或发送真实 QQ 消息。
