# 百度翻译命令

仓库根目录 `.env` 配置 `BAIDU_TRANSLATE_APP_ID` 和 `BAIDU_TRANSLATE_APP_KEY`，
填写百度翻译开放平台的通用文本翻译应用凭据，不是 QQ Bot 的 APP_ID/SECRET。
不要提交 `.env` 或把密钥粘贴到聊天中。配置后重启 Bot。
没有配置时，Bot 正常启动，调用翻译才提示未配置。

- `/翻译 Hello world`：自动识别原文并翻译成中文。
- `/翻译 /t en 你好`：翻译成英语。
- `/翻译 /f jp /t zh こんにちは`：指定源语言与目标语言。
- `/translate /t 日语 你好`：英文命令别名与中文语言名也可使用。
- `/帮助 翻译`：查看用法；参数放在文本之前。

`/f` 指定源语言，`/t` 指定目标语言，可交换顺序。默认源语言 auto，目标语言 zh。目标不能为 auto。常用代码 zh/en/jp/kor/fra/de；
其他小写语言代码会交给百度判断是否支持，以账号权限和官方语言表为准。
需要翻译以 `/` 或 `--` 开头的文本时，在正文前加独立的 `--`，例如 `/翻译 -- /help`。
沿用命令解析规则，连续空格/换行会合并，`&&` 是命令链分隔符，不适合原样翻译。

Bot 主动限制每次最多 1000 字符，成功后全局冷却 3 秒、执行中阻止并发；
失败不会进入成功冷却。HTTP 总超时 20 秒，不自动重试，避免重复消耗配额。
实际账户限额和计费以百度控制台为准；公共命令可能产生费用，请配置账号预算/配额。
译文超过 3500 字符会明确提示截断。测试只使用模拟响应，不消耗真实配额。

文本会发送给百度，请勿翻译敏感信息。命令记录仍按 Bot 原有机制保存，
新增客户端不记录原文、凭据、签名或上游原始错误。HTTPS POST 表单传参，
签名对未编码 UTF-8 原文计算，复用已有 aiohttp 依赖，无需安装 requests。

百度返回业务错误时，机器人回复和 WARNING 日志均显示错误码、中文含义和
处理建议，覆盖官方表中的全部 14 个失败码（包括 54000 和 58003）。
52000 按成功响应处理；未知数字错误码仍会显示，建议联系管理员查阅官方说明。
不直接回显原始 error_msg、请求体或完整响应。

参考：[官方接入文档](https://api.fanyi.baidu.com/doc/21)，
[官方签名与错误码说明](https://fanyi-api.baidu.com/doc_bd/21)。
